# تست و خطایابی

سامانه سه لایهٔ تست دارد؛ همه با یک دستور یا اسکریپت قابل اجرا هستند.

## ۱) تست‌های PHPUnit (واحد + ویژگی)

```bash
php bin/faraat test          # یا: vendor/bin/phpunit
```

**۱۳۸ تست / بیش از ۲۲۰۰ assert** روی پایگاه دادهٔ جداگانهٔ `faraatbafi_test`
(بوت‌استرپ در `tests/bootstrap.php` پایگاه تست را `migrate:fresh + seed` می‌کند).

### Unit (`tests/Unit/`)

| فایل | پوشش |

| `JalaliTest` | تبدیل‌های مرجع (نوروز ۱۴۰۳/۱۴۰۴/۱۴۰۵…)، رفت‌وبرگشت ۳۰ سال، سال‌های کبیسه (۱۳۹۹/۱۴۰۳)، طول ماه‌ها، قالب‌بندی، رقم فارسی/عربی، زمان نسبی، شمارش معکوس |
| `CodeGeneratorPatternTest` | کد مدل فنی، ترکیب SKU، **اعتبارسنجی همهٔ ۳۰ الگوی FUCS**، رد کدهای مخدوش، `detectType` |
| `ValidatorTest` | قواعد required/min/max/numeric/phone (با نرمال‌سازی +98)/melli/jalali_date (کبیسه!)/in/regex/confirmed، پیام‌های فارسی |
| `RouterTest` | تطبیق مسیر، پارامتر `{id:int}`، ۴۰۵/۴۰۴، گروه و ادغام middleware، رویدادها، helperها |

## ۲) اسموک‌تست HTTP (جریان سرتاسری روی سرور واقعی)

```bash
php bin/faraat serve &       # سرور باید در حال اجرا باشد
bash tests/smoke.sh          # ۷۲ بررسی
```

خزش صفحات نیز گسترش یافت: **۹۹ صفحه با ۶ نقش** شامل صفحات جدید (جست‌وجو، امنیت حساب، ممیزی، چاپ فاکتور/فیش، کشوی سبد).

سناریوی کامل با curl و کوکی نشست:
خرید مهمان (سبد→پرداخت→ORD→INV→کسر انبار) → ورود مدیر → تأیید سفارش → **WO خودکار (ED)** →
تخصیص بافنده + اعلان → توزیع مواد → پنل بافنده: دریافت مواد/شروع بافت/تحویل → ورود به انبار →
QC → **FB + PAY خودکار** → ماندهٔ بافنده → صفحهٔ اصالت با QR → POS نمایندگی + COM →
تیکت مشتری → ۴۰۳های RBAC → ۴۱۹ CSRF → ورود ناموفق.

## ۳) خزش صفحات (شکار خطاهای رندر)

```bash
bash tests/crawl.sh          # ۹۱ صفحه با ۶ نقش — هیچ ۵۰۰/۴۰۴ نابجایی نباید باشد
```

شامل بررسی ۴۰۳ بودن صفحات مالی/حاکمیت برای مدیر اجرایی (S) و ۴۰۴ بودن آدرس‌های جعلی.

## خطایابی

| ابزار | مکان |
|---|---|
| لاگ خطای PHP | `storage/logs/php-error.log` |
| لاگ سرور توسعه | `storage/logs/server.log` |
| صفحهٔ خطای دیباگ | با `APP_DEBUG=1` جزئیات استثنا + stack trace رندر می‌شود |
| لاگ رویدادها | جدول `activity_logs` (در صورت `app.log_events`) |
| مسیرهای ثبت‌شده | `php bin/faraat routes` |
| وضعیت ماژول‌ها | `php bin/faraat modules` |

### نکات تجربه‌شده در توسعهٔ این پروژه

1. **سرور توسعهٔ PHP کلاس‌ها را در حافظه نگه می‌دارد** — پس از تغییر کد، `php -S` را ری‌استارت کنید.
2. خطای `Class "Core\X" not found` یعنی فایل کلاس با نام کلاس در PSR-4 یکی نیست (یک کلاس = یک فایل).
3. در تست‌ها هرگز `Events::reset()` صدا نزنید — شنونده‌های ماژول‌ها پاک می‌شوند (از `Events::flush()` استفاده کنید).
4. برای دیباگ جریان‌های رویدادی: `Events::dispatched('workorder.qc_passed')` رویدادهای منتشرشده را نشان می‌دهد.
