# نظام کدگذاری یکپارچهٔ فرت (FUCS نسخهٔ ۳.۰)

ساختار کلی همهٔ کدها: `PREFIX – HISTORICAL/TECHNICAL_PART – UNIQUE_ID`

پیاده‌سازی: `core/CodeGenerator.php` — تولید با `GET_LOCK` + شمارندهٔ ترتیبی،
و اعتبارسنجی با Regex هم در PHP (`CodeGenerator::PATTERNS`) و هم در پایگاه داده (قید CHECK).

## ۱. کدگذاری محصولات (لایهٔ اصلی)

### الف) مدل فنی — `[TYPE]-[WEAVE][KNOT][STITCH]-CH[XX]`

| جزء | مقدارهای مجاز |
|---|---|
| TYPE | HT حولهٔ حمام، DS دستمال، SH شال، TN تن‌پوش، MO ملافه، FB پارچهٔ فرت، HC رومیزی، PC پوشاک، PR پرده، RB روبندک |
| WEAVE | `1L` یک‌لا، `2L` دولا، `3L` سه‌لا، `4L` چهارلا |
| KNOT | `B` بی‌گره، `G` گره‌دار |
| STITCH | `NS` بدون دوخت، `STD` استاندارد، `2N` دو سوزنه، `R` ریلی، `CUST` سفارشی |
| CH[XX] | چله × ۱۰ — مثلاً چلهٔ ۱۲٫۵ → `CH125` |

نمونه: `HT-2LBSTD-CH125` = حولهٔ حمام دولا، بی‌گره، دوخت استاندارد، چلهٔ ۱۲٫۵

```php
CodeGenerator::productModelCode('HT', '2L', 'B', 'STD', 12.5);
// → "HT-2LBSTD-CH125"
```

### ب) کتابخانهٔ رنگ و طرح

- **رنگ**: حرف خانواده + دو رقم صعودی — `R01` قرمز روناس، `I01` نیلی، `G01` سبز گیاهی…
  (`CodeGenerator::nextColorCode('R')` به‌صورت خودکار R07 را بر اساس MAX موجود می‌سازد)
- **طرح**: `P` + چهار رقم صعودی — `P0001` ترنج، `P0042`…
  (`CodeGenerator::nextPatternCode()` با شمارندهٔ سراسری)

### ج) SKU نهایی — `[MODEL]-[COLOR]-[PATTERN]`

```php
CodeGenerator::sku('HT-2LBSTD-CH125', 'R01', 'P0003');
// → "HT-2LBSTD-CH125-R01-P0003"
```

این کد یکتای فروشگاهی روی برچسب قیمت، انبار، اسناد فروش و API استفاده می‌شود.
در فرم ساخت واریانت، SKU به‌صورت **زنده (AJAX)** پیش‌نمایش داده می‌شود
(`POST /admin/catalog/sku-preview`) و تکراری بودن آن قبل از ثبت هشدار می‌گیرد.

### د) کد اصالت (مشتری‌محور) — `FB-[YEAR]-[SERIES]-[WEAVER]`

`FB-1403-0521-W023` → سال شمسی، سری ساخت (شمارندهٔ سالانه)، کد بافنده.

> طبق مستندات: QR باید حاوی **آدرس صفحهٔ اصالت** باشد نه کد خام:
> `https://faraat.ir/authenticity/FB-1403-0521-W023`
> پیاده‌سازی: `QR::authenticityUrl()` + `QR::authenticitySvg()` (خروجی SVG زرشکی برند).

صدور: به‌صورت خودکار پس از رویداد `workorder.qc_passed` (به تعداد qty، حداکثر ۲۵ در هر WO).

## ۳. مکانیزم تولید بدون برخورد

```php
CodeGenerator::nextCounter('order.1405');  // → 126
```

1. `GET_LOCK('fucs_' . md5(scope), 10)` — قفل نام‌دار MySQL
2. `SELECT last_value … FOR UPDATE` در تراکنش
3. افزایش و ذخیرهٔ `code_counters`
4. `RELEASE_LOCK` در `finally`

شمارنده‌ها **حوزه‌دار** هستند: سالانه (`order.1405`)، سالانه-بافنده‌محور (`payment.W045.1405`)
یا سراسری (`pattern`) — ریست سالانه خودکار با تغییر حوزه اتفاق می‌افتد.

## ۴. اعتبارسنجی سه‌لایه

1. **لایهٔ تولید** — `finalize()` هر کد را با Regex مرجع می‌سنجد (خطا = استثنا)
2. **لایهٔ پایگاه داده** — قید `CHECK (code REGEXP …)` روی همهٔ ستون‌های کد
3. **لایهٔ ورودی** — `CodeGenerator::detectType()` برای استعلام اصالت، کد کاربر را راستی‌آزمایی می‌کند

## ۵. قرارداد پاسخ API

هر خروجی ایجاد موجودیت، **کد تولیدشده را به‌همراه `id`** برمی‌گرداند:

```php
['ok' => true, 'order' => $order, 'code' => 'ORD-1405-000125', 'id' => 125]
```

و در UI، پیام‌های موفقیت همیشه کد را نشان می‌دهند:
«سفارش تولید «WO-1405-0006» ثبت شد. (id=6)»
