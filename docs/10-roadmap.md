# طرح توسعهٔ سامانهٔ فرت‌بافی (Roadmap)

> **نوع سند**: نقشهٔ راه — بدون پیاده‌سازی
> **تاریخ**: ۱۴۰۵/۰۷/۲۲ • **افق برنامه‌ریزی**: ۱۲ ماه • **مبنای تحلیل**: `docs/09-critique.md` + RFP مبدأ
> **شعار راهنما**: «اول تاب‌آوری، بعد قابلیت» — هیچ ماژول جدیدی پیش از بستن شکاف‌های امنیتی/عملیاتی فاز قبل شروع نمی‌شود.

## ۱. چشم‌انداز

رسیدن از **نمونهٔ پیشرفتهٔ فعلی (بلوغ ۳٫۳/۵)** به **سامانهٔ عملیاتی تعاونی (بلوغ ≥۴٫۵/۵)** که:
- تنها کانال ثبت سفارش تعاونی است (وب + نمایندگی + تلفنی یکپارچه)،
- چرخهٔ کامل «سهام‌دار ← بافنده ← مشتری» را با شفافیت مالی و حاکمیتی پوشش می‌دهد،
- روی زیرساخت تاب‌آور (CI/CD، مانیتورینگ، پشتیبان‌گیری، صف) سوار است،
- و برای رشد ۱۰ برابری (۱۰۰۰ بافنده، ۵۰ نمایندگی، فروش صادراتی) آماده است.

## ۵. فاز ۲ — توسعهٔ عملیات (مطابق RFP) | ۳ ماه

**هدف**: پوشش کامل لایه‌های ۴ تا ۶ RFP (انبار، مالی، لجستیک، نمایندگی پیشرفته).

### ۵٫۱ انبارداری پیشرفته
- **ماژول Warehouse** (جدید): پیاده‌سازی UI برای `LOC-*` (قفسه/ردیف/خانه) و `BOX-*` (بسته‌بندی)،
  انتقال بین موقعیت‌ها، **انبارگردانی دوره‌ای** با برگهٔ شمارش و مغایرت،
  نقطهٔ سفارش و پیشنهاد خرید مواد (بر اساس `min_stock` و مصرف ماهانه).
- بارکد/QR داخلی برای قفسه‌ها و بسته‌ها (اسکن با موبایل انباردار — PWA سبک).

### ۵٫۲ مالی پیشرفته
- **سند حسابداری دوطرفه**: جدول `journal_lines` (بدهکار/بستانکار)؛ هر رویداد مالی
  (فروش، دستمزد، پورسانت، خرید مواد) سند متوازن صادر کند؛ تراز آزمایشی ماهانه.
- صورت‌حساب دوره‌ای نمایندگی + تسویه با `credit_limit` پویا.
- گزارش‌های قانونی: فصلی مادهٔ ۱۶۹، ارزش افزوده، لیست بیمهٔ بافندگان (خروجی استاندارد).
- اتصال **درگاه پرداخت** (IPG): زرین‌پال/سامان — callback + تأیید دوگانه + تطبیق خودکار رسید.

### ۵٫۳ لجستیک
- API شرکت‌های حمل (پست پیشتاز/تیپاکس): نرخ‌گیری زنده، صدور بارنامه، **وب‌هوک رهگیری**
  → به‌روزرسانی خودکار `shipments.status` و اعلان مشتری.
- رهگیری مرسوله در صفحهٔ سفارش (timeline پستی).

### ۵٫۴ نمایندگی پیشرفته
- پنل موبایل نمایندگی (PWA): فروش آفلاین-first با صف همگام‌سازی.
- طرح‌های تشویقی پورسانت (پلکانی فصلی) و تسویهٔ خودکار پایان دوره.

### ۵٫۵ منابع انسانی
- حضور و غیاب پرسنل (ورود/خروج با کد) + مرخصی؛ کارکرد ماهانه → حقوق پرسنل (S).
- قرارداد بافندگان: نرخ دستمزد نسخه‌دار (تاریخ‌دار) تا تغییر نرخ، فیش‌های گذشته را عوض نکند.

**خروجی فاز ۲**: همهٔ جریان‌های مالی-انباری تعاونی در سامانه؛ حذف کامل اکسل موازی.

## ۶. فاز ۳ — بلوغ و هوشمندی | ۳ تا ۴ ماه

### ۶٫۱ هوش تجاری واقعی
- داشبوردهای قابل تنظیم (ویجت‌محور) + KPI targetگذاری و هشدار انحراف.
- گزارش‌ساز ساده (انتخاب ابعاد/سنجه با drag) روی لایهٔ تجمیعی روزانه
  (`daily_sales_agg`, `weaver_perf_agg` — ساخته‌شده با cron).
- پیش‌بینی تقاضا (seasonal naive + moving average در PHP یا سرویس پایتون جانبی)
  برای برنامه‌ریزی تولید نوروز/یلدا.

### ۶٫۲ مدیریت دانش و آموزش (لایهٔ ۵ RFP)
- **ماژول Knowledge**: کتابخانهٔ تکنیک‌های بافت (ویدیو/متن/الگو)، دسته‌بندی
  بر اساس نوع محصول و سطح مهارت؛ مسیر یادگیری کارآموز → استادکار.
- اتصال به پروفایل بافنده: دوره‌های گذرانده روی `skill_level` اثر بگذارد
  (ارتقای مهارت مبتنی بر شواهد، نه دستی).

### ۶٫۳ حاکمیت کامل
- **امضای دیجیتال مصوبات** (کلید داخلی + hash زنجیره‌ای) و بایگانی قانونی جلسات.
- رأی‌گیری محرمانه با audit trail رمزنگارانه (ballot رمز شده، شمارش عمومی).
- Workflow مکاتبات: ارجاع، مهلت، یادآوری خودکار، اندیکاتور نامه‌ها.
- پرتال سهام‌داران: افزایش سرمایه، انتقال سهام، **سود سالانه** بر اساس `shares`.

### ۶٫۴ CRM بالغ
- SLA تیکت (مهلت پاسخ بر اساس اولویت) + نظرسنجی پس از تحویل + باشگاه مشتریان
  (امتیاز خرید → سطح → مزایا).

**خروجی فاز ۳**: تصمیم‌گیری داده‌محور در هیئت‌مدیره؛ شفافیت کامل حاکمیتی.

## ۹. زیرساخت transversal (همراه همهٔ فازها)

1. **بازآرایی هسته**: تزریق وابستگی سبک (service locator → container)،
   PSR-15 middleware pipeline، contract برای payload رویدادها (DTO).
2. **کش**: Redis (یا فایل در استقرار تک‌سرور) برای: کاتالوگ، منوها، تنظیمات،
   تجمیعات BI؛ استراتژی invalidation بر اساس رویدادها.
3. **صف**: از queue جدول‌محور فاز ۰ به Redis-based (با همان API) در فاز ۲.
4. **CI/CD**: lint (php-cs-fixer, phpstan level 6+) → unit → feature → build image →
   deploy staging → smoke → production (blue-green ساده).
5. **پوشش تست**: gate از ۶۰٪ → ۸۰٪ تدریجی؛ افزودن تست race (دو خریدار، یک موجودی)،
   تست صف، تست‌های JS (Playwright) برای کشو/تم/فرم‌ها.
6. **مستندسازی زنده**: به‌روزرسانی `docs/` در هر PR (قانون تیم)؛ ADR
   (Architecture Decision Records) برای تصمیم‌های بزرگ.
