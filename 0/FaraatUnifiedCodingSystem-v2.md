# مستند مرجع نظام کدگذاری یکپارچه «فرت»  

## نسخه ۲.۰ — اردیبهشت ۱۴۰۳  
### Faraat Unified Coding System (FUCS) — Version 2.0

---

## پیش‌گفتار

این مستند مرجع کامل، منسجم و مقیاس‌پذیر نظام کدگذاری تعاونی «فرت» است.  
برای دو مخاطب طراحی شده است:

- **[👤 انسان]** : اعضای تعاونی، بافندگان، نمایندگی‌ها، انبارداران، حسابداران  
- **[🤖 ماشین]** : مهندسان نرم‌افزار و مدل‌های هوش مصنوعی برای پیاده‌سازی پلتفرم  

---

## اصول طراحی (مشترک)

1. **خوانایی انسانی** – هر کد برای کاربر نهایی معنادار باشد.  
2. **یکتایی مطلق** – هر کد در کل سیستم و در طول زمان منحصربه‌فرد است.  
3. **ساختار سلسله‌مراتبی** – پیشوند ثابت + بخش تاریخی/فنی + شناسه یکتا  
4. **قابلیت تولید خودکار** – بدون دخالت دست، بدون برخورد.  
5. **مقاوم در برابر خطا** – حذف حروف مشابه (I, O, …) و طراحی با طول بهینه برای تایپ.  
6. **مقیاس‌پذیری بی‌نهایت** – برای رشد تعداد اعضا، محصولات، رنگ‌ها، طرح‌ها و … محدودیتی وجود ندارد.

# بخش دوم: نظام کدگذاری محصولات (Enhanced Product Model)

این بخش جدیدترین و کامل‌ترین قسمت نظام کدگذاری است که تنوع بالای محصولات دست‌باف فرت را پوشش می‌دهد.

## ۱. مدل فنی محصول (Base Technical Specification)

این کد تمام ویژگی‌های فیزیکی و ثابت یک گونه از بافت را توصیف می‌کند.  
**الگو:** `[TYPE]-[WEAVE][KNOT][STITCH]-CH[XX]`

| جزء | توضیح | مقادیر ممکن | نمونه |
|------|--------|--------------|--------|
| **TYPE** | نوع محصول (همان ۹ دسته استاندارد) | `HT`، `DS`، `SH`، `PC`، `MO`، `TN`، `PR`، `HC`، `FB` | `HT` |
| **WEAVE** | نوع پودگذاری | `1L` (یک‌لا)، `2L` (دولا)، (آینده: `3L` و ...) | `2L` |
| **KNOT** | گره‌دار بودن | `G` (گره‌دار)، `B` (بی‌گره، پیش‌فرض) | `B` |
| **STITCH** | نوع دوخت | `STD` (استاندارد)، `2N` (دو سوزنه)، `R` (ریلی)، `CUST` (سفارشی مشتری) | `STD` |
| **CH[XX]** | شماره چله (تعیین‌کننده عرض و تراکم) | عدد چله × ۱۰ (برای جلوگیری از ممیز) | `CH125` (معادل چله ۱۲.۵) |

**تبدیل چله:** عدد چله واقعی = `CH[XX] / 10`  
مثال: `CH80` یعنی چله ۸.۰، `CH125` یعنی چله ۱۲.۵، `CH205` یعنی چله ۲۰.۵

**نمونه مدل‌های فنی:**
- حوله حمام دولا، بی‌گره، دوخت استاندارد، چله ۱۲.۵:  
  `HT-2LBSTD-CH125`
- دستمال سفره یک‌لا، گره‌دار، دوخت دو سوزنه، چله ۸:  
  `DS-1LG2N-CH80`
- شال سر دولا، بی‌گره، دوخت سفارشی، چله ۹.۵:  
  `SH-2LBCUST-CH95`

وزن تقریبی و قیمت پایه بر اساس مدل (و نه رنگ/طرح) در سیستم محاسبه می‌شود و وابسته به چله و لا است.  
تلورانس وزن (±۵ گرم) در فرآیند کنترل کیفیت لحاظ می‌شود.

## ۲. کتابخانه رنگ‌ها (Color Library)

رنگ‌ها از پالت برند و سایر رنگ‌های طبیعی استخراج می‌شوند. هر رنگ یک کد کوتاه و یکتا دارد:

| کد رنگ | نام | نمونه HEX |
|--------|------|------------|
| `R01` | قرمز روناس | #8B2E3A |
| `I01` | نیلی | #1A3B4C |
| `T01` | فیروزه‌ای | #1BA8A1 |
| `O01` | اخرایی زعفران | #C68A3C |
| `K01` | کرم پنبه‌ای | #FDFBF7 |
| ... | ... | ... |

کد رنگ مستقیماً در SKU محصول استفاده می‌شود.  
سیستم قابلیت افزودن رنگ‌های جدید را بدون محدودیت دارد.

## ۳. کتابخانه طرح‌ها (Pattern Library)

طرح‌ها و نقوش بی‌نهایت هستند. هر طرح یک شناسه یکتا دریافت می‌کند:

| کد طرح | توضیح |
|--------|--------|
| `P0001` | طرح راه‌راه ساده |
| `P0002` | لوزی سنتی تربت‌جام |
| `P0003` | بته‌جقه |
| ... | ... |

فرمت: `P` + عدد ۴ رقمی صعودی.  
با این ساختار، هر طرح جدید یک شماره جدید می‌گیرد و هیچگاه محدودیت شماره‌گذاری وجود ندارد.

## ۴. کد SKU نهایی (قابل فروش)

ترکیب مدل فنی + رنگ + طرح:

**الگو:** `[MODEL_CODE]-[COLOR]-[PATTERN]`

**مثال کامل:**
`HT-2LBSTD-CH125-R01-P0042`

این کد یکتای محصول در انبار، فروشگاه و اسناد مالی استفاده می‌شود و با یک نگاه ویژگی‌های زیر را فاش می‌کند:
- حوله حمام
- پود دولا
- بی‌گره
- دوخت استاندارد
- چله ۱۲.۵
- رنگ قرمز روناس
- طرح شماره ۴۲

**نکته:** کد SKU در جدول `product_variants` ذخیره می‌شود و از طریق آن به مدل فنی، رنگ و طرح لینک می‌شود.

# بخش چهارم: [🤖 ماشین] مشخصات فنی پیاده‌سازی

## ۴-۱. جداول جدید / اصلاحی در پایگاه داده

برای پشتیبانی از مدل جدید محصولات:

| جدول | فیلدهای کلیدی | توضیح |
|------|---------------|--------|
| `product_models` | `model_code` (PK), `type`, `weave`, `knot`, `stitch`, `chaleh`, `base_weight_grams`, `width_cm` | مدل فنی محصول |
| `colors` | `color_code` (PK), `name`, `hex` | کتابخانه رنگ |
| `patterns` | `pattern_code` (PK), `name`, `image` | کتابخانه طرح |
| `product_variants` | `sku` (PK), `model_code` (FK), `color_code` (FK), `pattern_code` (FK) | واریانت قابل فروش |
| `inventory_items` | `id`, `sku` (FK), `authenticity_code` (FK), `status`, `location_code` | هر قطعه فیزیکی |

سایر جداول (سفارش‌ها، فاکتورها و ...) به `sku` (واریانت) ارجاع می‌دهند.

## ۴-۲. تولید خودکار کدها

همان روش قبلی (مبتنی بر `GET_LOCK` و تراکنش) با اضافه شدن تولید کد SKU:

**تولید SKU:**  
از ترکیب رشته‌ای مدل، رنگ و طرح که از ورودی کاربر دریافت می‌شوند، ساخته می‌شود.  
یک `UNIQUE` constraint روی ستون `sku` از تکراری بودن جلوگیری می‌کند.

**تولید کد مدل:**  
مشابه الگوی ثابت با واکشی مقادیر از فرم و تولید رشته طبق الگو.

**تولید کدهای رنگ و طرح:**  
شمارنده ساده پشت `R`, `P` و... بدون ریست سالانه (تعداد نامحدود).

## ۴-۳. Regex Validation به‌روز شده

| کد | Regex |
|----|-------|
| مدل محصول | `^[A-Z]{2,3}-\d[L][GB](STD\|2N\|R\|CUST)-CH\d{2,3}$` |
| SKU | `^[A-Z]{2,3}-\d[L][GB](STD\|2N\|R\|CUST)-CH\d{2,3}-[A-Z]\d{2}-P\d{4}$` |
| کد رنگ | `^[A-Z]\d{2}$` |
| کد طرح | `^P\d{4}$` |

# بخش پنجم: سناریوی کامل روزانه (نمونه)

سناریوی قبلی با SKU جدید به‌روز شده:

1. مشتری «مریم» حوله‌ای با SKU `HT-2LBSTD-CH125-R01-P0042` سفارش می‌دهد → **`ORD-1403-000125`**
2. مدیر تولید سفارش را به بافنده «امید دروگر» (`W023`) می‌سپارد → **`WO-1403-0145`**
3. مواد اولیه خارج می‌شود: `RM-COT-R01` از `LOC-MAIN-B2-03`
4. بافنده تحویل می‌دهد و محصول کد اصالت **`FB-1403-0521-W023`** می‌گیرد.
5. کنترل کیفیت **`QC-1403-0023`** → قبول
6. بسته‌بندی و ارسال → **`SHP-1403-0041`** / **`BOX-140305-012`**
7. فاکتور **`INV-1403-00230`**
8. دستمزد بافنده: **`PAY-W023-1403-02`**
9. مریم QR را اسکن می‌کند → صفحه اصالت با اطلاعات مدل و بافنده ظاهر می‌شود.

# بخش ششم: راهنمای استفاده انسانی (خلاصه)

- **بافنده:** کد `WO...` را در پنل خود ببینید.  
- **انباردار:** کد `SKU` و `LOC...` را اسکن کنید.  
- **نمایندگی:** برای فروش حضوری کد `FB...` (روی محصول) را اسکن کنید.  
- **حسابدار:** کد `INV...`، `PAY...`، `COM...` را در گزارش‌ها پیگیری کنید.  
- **مدیر:** کد `MT...`، `RES...`، `VOT...` برای جلسات.

# بخش هفتم: نتیجه‌گیری

این نسخه نهایی نظام کدگذاری یکپارچه فرت، بر پایهٔ طراحی **مدل-واریانت** برای محصولات، **مقیاس‌پذیری کامل** را در تمام ابعاد سازمان تضمین می‌کند:

- تعداد نامحدود رنگ، طرح و حتی نوع محصول  
- قابلیت افزودن ویژگی‌های فنی جدید بدون تغییر در ساختار  
- حفظ خوانایی و معناداری برای کاربر انسانی  
- کاملاً قابل پیاده‌سازی خودکار توسط موتورهای نرم‌افزاری  

مستند حاضر به عنوان مرجع قطعی برای توسعه سامانه جامع مدیریت تعاونی فرت‌بافی از این پس مورد استفاده قرار می‌گیرد.
