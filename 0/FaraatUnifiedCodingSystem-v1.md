# مستند مرجع نظام کدگذاری یکپارچه «فرت» (Faraat Unified Coding System)

## نسخه ۱.۰ — اردیبهشت ۱۴۰۳  
### Faraat Unified Coding System (FUCS) — Version 1.0

---

## پیش‌گفتار: دو روی یک سکه

این مستند برای **دو مخاطب کاملاً متفاوت** طراحی شده است، با دو زبان و دو نگاه. هر بخش با برچسب مشخصی از دیگری تفکیک شده است:

- **[👤 انسان]** : ویژه‌ی اعضای تعاونی، مدیران، بافندگان، نمایندگی‌ها، انبارداران و حسابداران. زبان ساده، کاربردی و عملیاتی.
- **[🤖 ماشین]** : ویژه‌ی مهندسان نرم‌افزار، توسعه‌دهندگان فرانت و بک‌اند، و مدل‌های هوش مصنوعی برای پیاده‌سازی پلتفرم. زبان فنی، دقیق و قابل تبدیل مستقیم به کد.

## بخش صفر: فلسفه و اصول طراحی (مشترک)

**[👤 انسان]** چرا کدگذاری می‌کنیم؟
تا هر نخ، هر بافت، هر تومان و هر تصمیم، **قابل ردیابی** باشد. اگر مشتری از اصالت محصول پرسید، اگر بافنده از دستمزدش شکایت کرد، اگر نماینده‌ای موجودی انبار را ندانست — **کدها** پاسخگو هستند. این کدها زبان مشترک همه‌ی ما در تعاونی «فرت» است.

**[🤖 ماشین]** اصول فنی:
1. **خوانایی انسانی (Human-Readable):** هر کد باید تا حد امکان برای کاربر نهایی معنادار باشد (برخلاف UUIDهای تصادفی).
2. **یکتایی مطلق (Global Uniqueness):** هر کد در سراسر سیستم و در طول زمان منحصربه‌فرد است.
3. **ساختار سلسله‌مراتبی (Hierarchical Structure):** کدها از پیشوندهای ثابت + بخش‌های متغیر تاریخی/سازمانی + شناسه‌ی عددی تشکیل می‌شوند.
4. **قابلیت تولید خودکار (Auto-Generation Ready):** الگوی کدها به‌گونه‌ایست که می‌توان آن‌ها را با یک trigger دیتابیسی یا تابع PHP تولید کرد (بدون دخالت دست، بدون برخورد).
5. **مقاوم در برابر خطای انسانی (Error-Resistant):** حروف مشابه (مثلاً I و 1 یا O و 0) حذف شده‌اند. طول کد در حدیست که تایپ دستی آن ممکن باشد.

## بخش یک: ساختار کلی یک کد (مشترک)

```
┌─────────────────────────────────────────────────────────┐
│  PREFIX    -    HISTORICAL_PART    -    UNIQUE_ID        │
│ پیشوند ثابت     بخش تاریخی/موقعیتی      شناسه یکتا        │
└─────────────────────────────────────────────────────────┘
```

**مثال:** `FB-1403-0521-W045`

| جزء | مقدار نمونه | توضیح |
|------|-------------|--------|
| **پیشوند** | `FB` | معرف حوزه (Faraat Bafi / Product) |
| **بخش تاریخی** | `1403` - `0521` | سال و سری ساخت |
| **شناسه یکتا** | `W045` | بافنده شماره ۴۵ |

## بخش سه: [👤 انسان] — راهنمای استفاده در کار روزانه

### ۳-۱. کجا کدها را می‌بینم؟
- روی برچسب زرشکی رنگ کنار قیمت ← کد SKU
- روی کارت بافنده ← کد W...
- در پیامک تأیید سفارش ← کد ORD...
- روی جعبه‌ی ارسالی به نمایندگی ← کد BOX... و SHP...
- هنگام اسکن QR-code محصول ← کد FB...

### ۳-۲. اگر کدی را گم کردم یا اشتباه خواندم چطور؟
هر کد یکتا را می‌توانید در پنل خود جستجو کنید:
- **بافنده:** از منوی «سفارش‌های من» ← جستجوی WO...
- **نمایندگی:** از منوی «موجودی امانی» ← جستجوی SKU یا FB...
- **مدیر فروش:** از منوی «سفارش‌ها» ← جستجوی ORD...
- **حسابدار:** از منوی «گزارش‌ها» ← جستجوی ACC... یا PAY...

### ۳-۳. چه کدی را کجا وارد کنم؟
- مشتری برای **پیگیری سفارش:** کد `ORD...` را در کادر بالای سایت وارد کند.
- نمایندگی برای **فروش حضوری:** کد `FB...` (روی محصول) را با بارکدخوان اسکن کند.
- انباردار برای **خروج کالا:** کد `SHP...` را اسکن و به سفارش متصل کند.
- بافنده برای **اعلام پایان بافت:** کد `WO...` را در اپلیکیشن خود انتخاب و دکمه «تحویل به انبار» را بزند.

## بخش چهار: [🤖 ماشین] — راهنمای پیاده‌سازی در پلتفرم

### ۴-۱. قوانین کلی تولید کد (Code Generation Rules)

تمامی کدها در لایه‌ی **Model** و با یک متد استاتیک به نام `generateCode()` تولید می‌شوند. قوانین عمومی:

1. **پیشوند ثابت** بر اساس نوع موجودیت (از روی جدول mapping).
2. **بخش تاریخی/سازمانی:**
   - سال شمسی: از `jdate('Y')` یا `verta()` (کتابخانه شمسی).
   - ماه و روز: فقط در کدهایی که مشخصاً ذکر شده (کد اصالت).
3. **شناسه‌ی یکتا:**
   - یک شمارنده‌ی ترتیبی (sequence) که با قفل‌گذاری در سطح دیتابیس (MySQL `GET_LOCK()` یا تراکنش) از Race Condition جلوگیری می‌کند.
   - شمارنده می‌تواند سالانه ریست شود (مثلاً برای سفارش‌ها).
4. **بررسی یکتایی:** قبل از `INSERT`، یک `SELECT COUNT(*)` با WHERE روی کد تولیدشده انجام شود. در صورت برخورد، بازتولید (retry با تأخیر تصادفی).

**نمونه‌ی شبه‌کد برای تولید کد سفارش:**

```php
function generateOrderCode($year) {
    $this->db->beginTransaction();
    $lockName = 'lock_order_code_' . $year;
    $this->db->query("SELECT GET_LOCK('$lockName', 10)");
    
    $maxSeq = $this->db->query(
        "SELECT MAX(CAST(SUBSTRING_INDEX(code, '-', -1) AS UNSIGNED)) 
         FROM orders WHERE code LIKE 'ORD-$year-%'"
    )->fetchColumn();
    
    $nextSeq = str_pad(($maxSeq ?? 0) + 1, 6, '0', STR_PAD_LEFT);
    $code = "ORD-$year-$nextSeq";
    
    $this->db->query("SELECT RELEASE_LOCK('$lockName')");
    $this->db->commit();
    return $code;
}
```

### ۴-۳. اندیس‌گذاری و Performance

تمام ستون‌های `_code` باید دارای **UNIQUE INDEX** باشند. برای کدهایی که با سال شروع می‌شوند، می‌توان از **PARTITION BY RANGE** روی سال (اگر MySQL 8) استفاده کرد، اما با توجه به مقیاس پروژه (۱۰۰ بافنده، ۲۰۰ مشتری ثابت) نیازی به پارتیشن‌بندی نیست و یک INDEX ساده کافیست.

### ۴-۴. API Response Format (برای فرانت‌اند)

هرگاه یک کد جدید تولید می‌شود (مثلاً پس از ثبت‌نام بافنده)، پاسخ API باید بدین شکل باشد:

```json
{
  "status": "success",
  "data": {
    "id": 45,
    "weaver_code": "W045",
    "full_name": "سلیمان دروگر"
  }
}
```

و **نه** صرفاً `id=45` بدون کد. فرانت‌اند باید بلافاصله کد را در UI به کاربر نشان دهد.

### ۴-۵. تولید QR Code برای کد اصالت

کد اصالت (`FB-1403-0521-W045`) باید به یک QR Code تبدیل شود که حاوی URL زیر باشد:

```
https://faraat.ir/authenticity/FB-1403-0521-W045
```

**نه** خودِ کد خام. این URL به یک کنترلر (مثلاً `AuthenticityController@show`) هدایت می‌شود که اطلاعات کامل محصول، بافنده و گواهی اصالت را به‌صورت یک صفحه‌ی زیبا (مطابق با UI Kit پروژه) نمایش می‌دهد.

## بخش پنج: سناریوی کامل — یک روز از زندگی یک کد

**[👤 انسان]** فرض کنید مشتری‌ای به نام «مریم» از بازارگاه فرت یک حوله می‌خرد. در پشت صحنه چه کدهایی تولید می‌شود؟

1. سفارش مریم ثبت می‌شود ← **`ORD-1403-000125`** (پیامک می‌شود)
2. مدیر تولید سفارش را به بافنده «امید دروگر» (کد **`W023`**) تخصیص می‌دهد ← **`WO-1403-0145`**
3. مواد اولیه (نخ پنبه روناس) از انبار خارج می‌شود ← **`RM-COT-R01`** از **`LOC-MAIN-B2-03`**
4. بافنده کار را تمام می‌کند و محصول با کد اصالت **`FB-1403-0521-W023`** به انبار محصول می‌رود ← **`LOC-MAIN-A1-12`**
5. کنترل کیفیت بررسی می‌کند ← **`QC-1403-0023`** (نتیجه: قبول)
6. سفارش بسته‌بندی و ارسال می‌شود ← **`SHP-1403-0041`** در کارتن **`BOX-140305-012`**
7. فاکتور صادر می‌شود ← **`INV-1403-00230`**
8. دستمزد بافنده محاسبه می‌شود ← **`PAY-W023-1403-02`**
9. مریم QR-code روی حوله را اسکن می‌کند و به آدرس `faraat.ir/authenticity/FB-1403-0521-W023` می‌رود. آنجا می‌بیند که این حوله را «امید دروگر» در ۲۱ اردیبهشت ۱۴۰۳ بافته است.
